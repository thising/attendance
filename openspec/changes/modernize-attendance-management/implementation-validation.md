## 查询与恢复演练

| 合成场景 | 实际结果 |
| --- | --- |
| 50人各一条异常，完整提交 | 13条SQL（含事务）；加入600行无关历史次数缓存后仍13条 |
| 50人、12个月、600条报告，当前学期报表 | 9条SQL，含5条SELECT；单次本机4.144毫秒 |
| 删除一条含50条报告的当月记录 | 12条SQL，单次本机4.123毫秒；报告600→550，当月缓存归零，五个月均分59.00→59.20 |

这些数字只代表本机合成测量。SQLite依赖短事务串行协调写入；读报表也保持一致快照，避免一次页面内混用规则版本。生产容量仍需在目标设备实测。

原库副本的结构升级、密码散列、原始日期和计数保全以及备份恢复已经验证，详见 [发布准备与回滚](release.md) 和 [演练结果](rehearsal-result.json)。现有旧库历史导入不会通过清除待核实标志来放行；差异清单见 [历史分数差异](legacy-score-differences.md)。
