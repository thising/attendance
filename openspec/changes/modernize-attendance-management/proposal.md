## 当前任务：R10预生成公开报告（2026-09-24）

## 当前任务：R9本地实现（2026-09-24）

班主任和班委登录在同一用户名连续5分钟内错误8次后阻断30分钟。点名未保存时站内导航需确认；名单变化后不沿用旧状态，刷新名单重新点名。历史只读页使用中性灰视觉；当前学期学生成绩表姓名配男女SVG符号。班级月度明细下拉覆盖本学期已进入月份；记录列表的“记录人数”按考勤异常、活动和违纪非零权重计算。

匿名用户通过班级固定高强度链接仅查看**当前学期**个人汇总和逐月报告，不设置学生账号。班主任和本班班委可启用并取得链接/二维码用于分享；更换、停用仅班主任可做。令牌由独立密钥加密保存、摘要索引，不采用原班级码；8月不展示已结束学期报告。正式域名二维码及分享范围在发布前核对，线上暂不启用。

## 当前任务：R8最新数据口径、活动详情与历史快照（2026-09-24）

本地验收必须以VPS207 `managedb.sqlite3`新的SQLite一致性快照为来源，逐字段保留原始业务事实、逐人比较九类次数和分数；不能把早先的36条活动当成持续有效的线上基线。线上仍在录入时，任何本地副本都只能代表采集时点。正式切换前须停旧系统写入、另取最终快照，使用已验证的生产专用迁移桥接，核对五张业务表及每人评分，差异为零才准切换；如来源改变则重新采集与演练。此条是发布门槛，不代表本轮已获部署授权。

活动增加可选详情，旧记录详情为空，旧名称原样保留；统一允许1–64字名称、最多500字详情。已结束学期以`ClassTerm.archived_data`固定名单、政策、月度分数和业务记录事实，历史班级/个人/记录/名单页均从快照读取。学期结束后第一次读取会把有可信当期名单依据的事实冻结成快照；已核定的既有归档绝不重算、覆盖或从实时记录补齐，缺少记录快照要显示待核实。当前学期继续即时计分并允许权限内修正；8月与已结束学期均禁止业务写入。

已有的实验性OpenAPI文档暂保留作历史草案，**Agent接口合同的修订、定稿及接入延至本版本上线以后**，不作为本轮发布条件。学生只读模式本轮仅评估数据架构，不创建学生账号或开放数据入口。

## 2026-09-23 生效修订（R3，本地已验收）

本节与同步能力规格是当前依据，覆盖R2的固定月度60/0/无上限、全历史累计、全局混排导航及仅保存不可逆班委密码约定；其他历史只读、单班权限、5个启用账号和3小时会话继续有效。

- 月度基础分、下限、上限与九类权重一起版本化；默认60/0/无上限，值域0–999999.99、最多两位小数，下限≤基础≤上限（上限可空）。先逐月截断再平均；修改立即影响本人全部班级当前及未来学期，历史规则和成绩不变。
- 班级累计活动次数按上方所选学期发生日期统计全部三类记录，默认当前学期；最近录入时间也限此学期。班级人数使用该学期有效名单。
- 班级详情恢复本月/上月完整九类次数和月分，姓名/月分关联该学生该月明细。跨学期使用该月原名单与评分依据；新生历史未在册不补造分数，8月不计分。历史页面显示所选学期期末两月并明确年月。
- 系统层导航仅工作台、评分规则；班级总览、快速录入、班级管理、日志放入明确班级上下文的局部导航，保留学期与班级切换。
- 学生汇总恢复旧版视觉锚点：非零扣分朱砂、非零加分青绿、零值弱化，均保留数字与图形/文字。个人分数相对其当时月度基础值标记高低，不新增合格阈值或班级排名。
- 每班固定唯一4位小写十六进制hash前缀；完整班委用户名为`<prefix>.<username>`，同班短名唯一、跨班可同名，前缀与完整账号建立后不可更改。旧账号迁移添加前缀并撤销旧会话，历史日志不回写用户名。
- 用户明确要求班主任**随时复制完整用户名和密码**，因此增加独立密钥加密的密码副本，散列继续用于登录。仅所属班主任通过受CSRF保护的POST按需读取，响应禁止缓存；页面组合产品/班级/用户名/密码为一段文本并复制到剪贴板，失败可手动选中复制。不保存浏览器持久副本，不将密码写日志或幂等回执。
- 原有散列无法还原，已有账号重置一次后才提供随时复制；不使用旧散列冒充密码。新增/重置后加密副本与账号、日志同事务保存；密钥独立保存并与库备份配套，真实部署需显式配置。

## 2026-09-23 历史修订（R2，冲突内容由R3覆盖）

本节保留R2历史决策，取代首轮关于共享密码、班级码、班均分和“补录学生”的约定。首轮验收记录保留为历史证据，本轮结果单独记录于实施验收记录的R2节。

- 统一称“新增学生”；业务生效期不变，仅加入当前学期。恢复原Excel模板下载，新增受限xlsx上传解析与预览，也可复制Excel前三列或粘贴原竖线格式；预览不写库，最终整批校验后一次保存。
- 班级主信息为人数、累计活动次数（所有类型/历次活动）、最近活动时间（最近创建时间）；班级与工作台不显示班均分。操行分表现对象是个人，规则影响预览显示影响学生数、个人分数变化人数和最大个人分差。
- 工作台默认展示名下所有班级的全体学生学期概况，恢复旧九类次数与个人学期分，加班级标识；提供多班筛选、姓名/学号查找。历史仍按独立名单与历史规则展示。
- 首页提供班主任登录、班委登录两个渠道，默认班主任。负责人后台角色仍为owner，界面称班主任。

- 停用共享密码认证及旧班级码入口。数字班级ID仅作URL对象定位，不能代替权限；旧数据库字段暂仅作迁移证据保留，不再读取其值认证或展示。
- 原始旧库仍不修改。新增迁移和账号演示仅在独立开发库验收；历史导入和部署保持独立审核门槛。

旧版与首轮的信息差异、恢复理由见 [信息架构评估](information-review.md)。

## Why

现有系统已覆盖班级、学生、考勤、活动、违纪及汇总，但存在写入权限遗漏、跨班操作、网络重试重复提交、学期边界与汇总维护错误。负责人还需要统一设置其所有班级的评分权重。此次以一套业务服务支撑页面和未来 Agent 调用，保留简单部署方式，并重新设计适合艺术设计专业内部使用的操作界面。

| 图标与文字 | 操作控件和标题采用图标与文字结合，图标风格统一并契合整体视觉，提供清晰的视觉定位 |

已结束学期冻结**名单、业务记录、评分依据和成绩**，负责人也不能通过页面、后台或未来 Agent 改动。当前学期内允许补录和修正此前月份的记录，仍须符合角色权限。当前名单增删、姓名修改及新权重不能反向改变已结束学期；历史数据初次迁移的差异另行审核，不默认为允许历史纠错。

用户已认可当前样稿的“当代书院”国风主体及图标文字组合：纸白、墨色、朱砂、宋体标题和册页式分栏。Logo已选定 B“竹节”，使用不含文字的双竹图案，配朱砂竹节；“笃行”和小标题继续作为独立文字标识保留。后续用户已授权按推进计划开始实施，并允许直接使用本地浏览器测试；该授权不包含部署或修改真实业务数据库。

## What Changes

1. 统一老师身份与班级临时授权，所有写入检查班级范围、权限、学期状态和提交编号。
2. 提取学期日期、评分和记录修改服务；当前学期自然月补基础分、记录修正和重建使用同一算法。
3. 新增负责人评分规则、规则版本、学期名单及归档依据，当前学期即时生效，已结束学期整体只读。
4. 重做工作台、班级详情、快速录入、学生明细、评分规则和权限状态等核心界面。
5. 建立受版本控制的迁移、依赖与回归测试；分阶段迁移到 Python 3.12 + Django 5.2 LTS 的受支持补丁版本。
6. 页面使用统一业务服务；现存Agent合同与样例保持未启用草案，正式合同及机器凭据、写 API、MCP接入均在本版本上线后另行设计和验收。
7. 为每个班级提供概要事件日志，覆盖录入、修改、删除、名单补录和规则更新，负责人可查看。

## Capabilities

### New Capabilities

- `class-access`: 班级授权、负责人权限、提交幂等、班级隔离。
- `term-scoring`: 学期日历、自然月计分、当前学期修正、历史归档和汇总一致性。
- `owner-scoring-policy`: 负责人权重、规则版本及历史学期规则冻结。
- `professional-workspace`: 桌面/手机工作台、录入和评分设置的完整交互。
- `agent-contract`: 可复用业务接口、结构化合同、身份范围与审计设计。
- `class-event-log`: 面向班级负责人的不可编辑概要事件日志。

### Modified Capabilities

无已有 OpenSpec 能力基线；本次不宣称现有实现已符合新增规范。
