## 1. 架构与边界

保留 Django 模块化单体、服务器模板和 SQLite，前端采用统一设计变量及适量原生 JavaScript。表格录入、局部预览用组件增强，不为本次内部系统另引入独立 SPA、微服务或任务队列。实施运行基线为 Python 3.12.13 + Django 5.2.17；独立 .venv-duxing 使用 requirements.txt 锁定依赖，不读取原 attendance/settings.py。Django补丁版本按2026-09-22官方 https://www.djangoproject.com/download/ 核对。

分离以下职责，HTML、后台和未来 API 复用：

- `services/access`：负责人/班委/机器身份、对象归属、角色权限、已结束学期及八月写入限制。
- `services/records`：校验、幂等、并发版本检查、活动与报告事务、受影响月份计算。
- `services/calendar`：日期归属、完整月份集合、当前/上一学期、只读期间判断。
- `services/scoring`：批量次数统计、学期规则解析、月分和学期平均、规则影响预览。
- 查询职责落实在 `services/scoring` 和视图的数据适配层：整班/多班聚合及详情预取，避免模板中逐个学生访问数据库。

沿用 Asia/Shanghai 业务日期。数据库时间迁移与业务发生日期分开处理；新增/补录使用明确的活动发生日期，创建时间另行保留。旧 `Activity.time` 回填发生时间，不用服务器迁移时间覆盖。首版拒绝未来活动日期，防止未来月份提前入账。

## 2. 权限、写入和防重

班主任按 `Class.owner` 授权。班委使用独立 `CommitteeAccount`，用户名全局唯一且统一小写，每个账号固定一个班级；每班最多5个启用账号，在SQLite写事务内检查名额。完整用户名由Class.committee_prefix固定4位hash和短名组成，前缀唯一且不可改，短名可跨班复用。班级数字ID仅为URL定位，不具有授权能力。旧sharecode/managecode/grant_version字段暂留迁移证据，现行代码不再用它们认证。

登录分班主任和班委两个渠道，首页默认班主任。班委在服务器Session保存account_id、auth_version和固定3小时expires_at，普通访问不续期；每次业务请求复核启用状态和版本。班主任可停用/启用、改显示姓名和重置密码；停用或改密使旧会话失效。用户名及班级不能经更新操作转移，停用账号保留历史日志。失败登录按账号持久化限流，不因清除浏览器Cookie而重置。

恢复录入时保持原账号、UUID和actor_context；同一账号重新登录/改密不改变幂等身份，换账号不能误重试原草稿。登录密码保存散列，并按用户R3要求保存Fernet加密副本以便班主任随时复制；独立DUXING_CREDENTIAL_KEY，开发密钥为权限600的.local/credential.key。提交摘要为HMAC，普通账号列表/幂等回执/日志不含密码；仅owner专用POST按需解密并返回no-store响应。修改前已备份本批源码和开发库，可恢复到上一批配对版本。
每个写入口依次验证：身份 → 班级范围 → 动作权限 → 业务只读状态 → 请求格式及对象版本。活动通过授权班级的关联集合获取，学生必须属于同班。正常 CSRF 校验继续保留。班级授权过期时表单内容留在当前页面，重新验证后继续；避免在浏览器持久存储学生敏感名单。

班委身份显示账号与班主任填写的显示姓名；它是已认证账号及管理者指定信息，不宣称外部实名验证。旧共享授权日志保持旧身份标签，不反推个人。

提交编号不能代替身份或 CSRF。幂等键绑定身份/授权上下文、班级和操作类型，并保存请求摘要与结果引用。数据库唯一约束及事务保证同一请求只生效一次；相同编号不同内容返回冲突，成功重试返回第一次结果。后续被删除的结果返回已删除状态，不能重建活动。多标签页使用独立编号。编辑使用记录 revision，旧版本提交提示冲突，禁止默默覆盖新修改。

班级管理的清空与删除只限班主任和当前学期，并要求页面 revision、独立提交编号及完整班级名称确认。清空数据仅删除当前学期考勤/活动/违纪事实和相应派生月缓存；清空学生仅在当前学期已无业务记录时执行，历史身份继续保留。删除班级只允许当前名单、当前记录均为空且不存在历史学期资料的班级；班委账号和公开链接随空班删除失效。三个动作均不能改写已结束学期快照。

批量新增在预览和提交阶段共用同一名单校验：同批学号重复或与本班当前名单重复时整批拒绝，数据库 `(inclass, number)` 唯一约束继续兜底。曾从当前学期移出的同学号学生允许重新新增，复用原学生身份和当前学期名单版本，并以本次姓名、性别恢复在册；预览明确显示恢复人数。

非负责人每日新增限制保留 30 条/班的既有约束，按服务器创建日检查，不能通过回填历史日期绕过；负责人仍豁免。并发配额与幂等在同一写入事务中处理。SQLite 不依赖 `select_for_update` 提供行锁保证；唯一约束、短事务和有界冲突重试需要多连接测试。

活动、报告、受影响月份缓存和必要审计在同一次事务内提交。主要写流程从逐条信号迁移到业务服务；Django admin 和维护脚本必须同步接入或限制为只读，避免绕过。异常明确返回，不再把所有异常当成“不存在”。

## 3. 学期日历和自然月计分

| 学期 | 半开日期范围 | 完整月数 |
| --- | --- | --- |
| `2026-spring` | 2026-02-01 ≤ 日期 < 2026-08-01 | 6 |
| `2026-autumn` | 2026-09-01 ≤ 日期 < 2027-02-01 | 5 |

当前学期只纳入从学期开始到当前自然月的月份；历史学期使用完整范围。每个月即使没有活动也有该学期规则的月度基础分（默认60）。8 月没有当前学期，默认显示最近完成的春季；旧八月数据保留在历史月报/明细中，明确标为学期外。

月份集合由日历生成，不由 `SummaryCount` 是否存在决定。无实际事件的月返回零次数；存在事件而缓存缺失时按明细计算或重建，不能当作无事件。新增学生只加入该班当前学期名单，按当前学期全部已进入月份计分，不以新增日期截断，也不向已结束学期补人。个别学生转入/退出期间不在本次范围。

月分先计算`基础分 + 奖励合计 - 扣分合计`，再限制在月度下限/上限（可空）的范围；学期分数为纳入月份月分的平均。默认60/0/无上限，先逐月截断再平均。权重、计分使用 Decimal，权重最多两位小数；月分保留精确两位，学期平均在展示/输出时采用统一两位四舍五入规则。

8 月写入边界按服务器业务日期判断，不能靠客户端日期或伪造历史发生日期绕过。提议暂停活动、报告、名单、评分设置的业务写入；登录、退出、撤销凭据仍可用。该范围按已批准 D3 执行。

### 3.1 已结束学期只读与名单隔离

已结束学期只允许查看，不允许新增、补录、修改、删除或更改审核标记；负责人、班委、后台、维护入口和未来Agent遵守相同规则。当前学期内可以修正此前月份，活动改期时旧日期和新日期均须属于当前学期，禁止通过改日期将记录移入或移出历史学期。提交时依据服务器业务日期复核，跨学期未提交的旧表单不能继续写入。

采用班级/学期独立名单（如 `ClassTerm` / `StudentTermMembership`），保留当期姓名、学号、班级及归属快照，并绑定当期事实、规则与算法版本和最终报表基线。新学期继承有效名单；此后补人、移除或改名仅影响允许修改的当前名单，历史展示使用归档身份。涉及历史引用的学生和班级使用归档或受保护删除，禁止现有级联删除连带清除历史事实与日志。

只读立即由日期决定，不依赖定时任务。归档物化可定时或延迟执行，但任何可能影响历史的名单/身份变更必须先在同一一致性边界内保全上一学期依据；跨学期并发提交需重新检查日期并拒绝越界写入。完全未访问的学期也必须能从保留的名单有效期与不可变版本还原，不能用首次访问时的现行名单补写历史。具体表结构在迁移基线核实后确定，须以历史名单和分数不变为验收条件。

## 4. 负责人评分规则与版本

评分设置挂在负责人层级，入口位于全局导航，不放在某个班级的局部设置里。所有当前名下班级共享一套当前学期规则。

| 字段 | 默认分值 | 方向 |
| --- | ---: | --- |
| 缺勤 | 2 | 扣分 |
| 迟到 | 1 | 扣分 |
| 请假 | 0 | 扣分 |
| 班级活动 | 1 | 加分 |
| 院级活动 | 3 | 加分 |
| 校级活动 | 5 | 加分 |
| 轻度违纪 | 5 | 扣分 |
| 中度违纪 | 8 | 扣分 |
| 严重违纪 | 12 | 扣分 |

全部输入非负分值，方向由类别决定。正常出勤/未参加/无违纪为零，不新增可配类别。字段使用明确的 Decimal 字段及服务端范围验证，不用不受约束的任意公式。

建议数据结构：

- `OwnerScoringSettings`：负责人唯一，指向未来学期默认规则，带 revision。
- `ScoringPolicyVersion`：不可变九类权重、基础算法版本、创建者/时间、生效学期和变更摘要。
- `OwnerTermPolicy`：负责人 + 学期唯一，指向该学期规则版本。当前学期可以重新绑定新版本，已结束学期禁止由权重设置更新。
- `ClassTerm` / `StudentTermMembership`：独立学期名单与历史身份快照；归档关联固定规则、算法与报表基线，不引用可变的当前名单解释过去。
- `SummaryCount`：仅缓存学生/年月的九类次数，增加唯一约束；分数不作为不可更新的权威列。
- `Submission` / `AuditEvent`：请求去重及必要操作追溯，避免记录密码、token 或无关个人信息。

一次权重保存流程：验证负责人及表单 revision → 预览受影响班级/学生和当前学期分数差异 → 事务写入新规则版本 → 更新当前学期绑定和未来默认 → 返回当前学期最新汇总及版本。界面只在事务成功后显示“已应用”。如果预览期间发生记录变化，保存结果以最新事实重算，提示差异已刷新。

所谓“立即更新”是评分规则事务提交后，新请求/本页刷新使用新权重，不要求批量改写所有历史明细。缓存键含负责人、学期、规则版本和数据修订号；第一版不缓存最终分数可进一步降低陈旧风险。不能承诺已经打开的其他浏览器无交互瞬间变化；它们在重新进入/刷新时获取最新值。

当前学期更换权重，对整个当前学期生效，不分“修改前后发生”的事件。未来学期首次启用时绑定对该学期有效的默认版本：根据规则版本的生效学期和提交时间确定，不能直接取访问时的最新指针。即使某个学期完全未访问，之后首次查看时也必须还原当期可用的最后版本。学期是否已结束由日期直接判定，不依赖定时任务何时创建锁标记。

历史学期在迁移时显式绑定旧硬编码规则，不能在以后首次访问时绑定当时最新默认。已结束学期的报告、名单、权重和成绩均不可修改，历史读取使用固定依据。首版禁止直接转移班级负责人，含 Django admin，避免历史归属和规则漂移。

## 5. 数据一致性与性能

每次当前学期写入收集 `(student_id, year, month)` 集合；若活动日期允许修改，需要同时包含当前学期内的旧月和新月。报告全部修改完成后，对受影响集合做条件聚合，再批量 upsert 次数缓存，或在读路径按同一选择器聚合。删除最后一条记录后次数归零，月份仍按日历计基础分。

重建从 Report/Activity 的事实出发，能创建缺失月份并校正错误次数；不由已有缓存决定范围。提供只读差异预览和显式应用步骤。已结束学期仅允许不改变归档名单、事实及最终成绩的派生缓存重建；若与归档基线不一致，只报告差异，不自动覆盖成绩。Student `(inclass, number)`、Report `(activity, student)`、SummaryCount `(student, year, month)` 及学期名单均增加对应业务唯一约束；发现旧重复先列冲突，禁止静默丢弃。

首版继续 SQLite，设置适当 busy timeout、有界重试和短事务；不宣称与 PostgreSQL 并发等价。验收以查询数随受影响范围增长、错误恢复及目标数据规模的延时为准；在目标环境未核实前不承诺固定毫秒指标。若 Agent 或多人写入实测达到瓶颈，再独立评估 PostgreSQL。

## 6. 信息架构与专业界面

已展示界面的“当代书院”国风主体获得用户认可：纸白底、墨色正文、朱砂强调，借用册页分栏和细双线；轻微纸感只用于留白区域，名单和输入区域保持纯净。标题使用清晰宋体，品牌使用楷体；姓名、学号、数字和操作文字保持易读的现代字体。浅色与深色分别配置色值，状态使用文字、图形和颜色共同表达。Logo按用户要求另行改为图案标志，原“笃”字印章不作为最终Logo。

用户已选定 B“竹节”作为 Logo 方向：双竹与三片叶构成图案，主色为墨绿，右侧竹节以朱砂点缀；不包含文字、印章边框或渐变。“笃行”及“学生操行管理系统”保持独立文字排版。其余三个候选不再作为当前设计依据。

品牌资产位于本变更的 `assets/`：`duxing-bamboo.svg` 为标准矢量图案，`duxing-bamboo-mono.svg` 为相同轮廓的单色版本；`duxing-bamboo-small.svg` 用于16–24像素场景，以两片叶和更大的竹节留白保持辨识度。标准图案从32像素起使用，导航栏采用40像素，手机导航采用32像素；不拉伸比例，四周留白至少为图案宽度的1/8。SVG透明底，浅色使用墨绿/朱砂，深色切换浅竹青/浅朱砂；固定底色使用时应显式指定相应配色。带相邻产品文字时图案隐藏于读屏，独立使用时提供“笃行”可访问名称。正式工作台已开始接入该资产，实际页面状态以任务验收结果为准。

产品名称已确认为“笃行”，小标题固定为“学生操行管理系统”；组合展示为“笃行 · 学生操行管理系统”。主标识突出“笃行”，小标题说明用途；登录页、全局导航、浏览器标题和后续报表采用统一命名。备选配色为“青瓷墨色”“竹青纸白”，不改变布局和操作位置。

按用户已确认要求，导航、页面标题、主要区块标题和操作按钮采用图标与可见文字结合。使用同一套细线单色图标、统一笔画与尺寸，默认随正文或强调色显示；样稿沿用Lucide图标体系，品牌印章作为装饰与功能图标分开。班级使用书册、录入使用点名板、活动使用奖章、违纪使用警示盾牌；保存、撤销、预览分别使用保存、回转箭头、眼睛的通用含义。同一功能在导航、标题和按钮上保持一致。

学生状态也提供语义图标：迟到用时钟、缺勤用缺席人物、请假用日历，选中后显示勾选和状态文字。图标属于按钮整体点击区域，避免添加额外点击步骤；在320像素窄屏保留文字及至少44像素高的触控区。图标对读屏隐藏，控件名称由文字提供；图标加载失败时文字和操作仍可用。国风装饰不得覆盖数字、缩小触控区或改变默认正常、单击标记、撤销及保存反馈的行为。

| 评分规则 | 九类加减分、当前与未来生效范围、影响预览、保存结果；历史规则只读查看 |
| 班级管理 | 新增学生与校验、单班班委账号管理；危险操作与高频录入分开 |

桌面用稳定导航和可扫描表格；手机将学生行变为易点击的紧凑条目，主提交按钮保持容易找到但不遮挡内容。指定的独立账号用户标记为“班委”，只看到其可用导航；已结束学期显示“已结束 · 只读”，不提供修改入口，8月另显示暂停录入原因。普通录入突出“保存即计分”，保留旧审核标记但不制造待审批队列。

所有页面包含加载、空状态、输入错误、权限过期、保存失败、重复提交已处理、编辑冲突及只读状态。权重保存使用影响预览与明确提交，不用输入即自动保存。删除显示具体活动及受影响记录数；当前学期修正保留必要审计。

以 WCAG 2.2 AA 为验收目标：键盘完整操作、可见焦点、表单标签、文本对比、触控目标和错误提示。不是完成样稿就宣称无障碍验收通过。

交互样稿仅使用虚构数据，覆盖班级工作台、快速录入和评分规则联动；其布局和业务交互供审核，未连接真实后台。

### 6.0 点名操作

顶部直接展示“考勤点名 / 活动加分 / 违纪扣分”，不要求先打开下拉。学生行固定展示四个互斥按钮：考勤为“到课 / 迟到 / 缺勤 / 请假”，活动为“未参加 / 班级 / 院级 / 校级”，违纪为“正常 / 轻度 / 中度 / 严重”。点击一次即选中，以文字、勾选和底色反馈；重复点选当前状态不翻转，不使用循环切换或滑动作为必要操作。选错时可以直接点正确状态，或撤销最近一步。

学生按学号固定排列，姓名与学号一起展示，点选不重排行列；搜索或筛选不丢失隐藏学生状态。沿用默认正常/未参加的业务约定，但默认值不代表已逐一点名；汇总只显示各状态人数，保存前展示异常姓名和状态供核对，不标称“全部已核验”。每人不弹确认框，全班最后一次明确提交。手机按钮触控区域至少44像素高，窄屏姓名与按钮分两行，不压缩为下拉。

提交区展示总人数、分类人数、异常名单及“未提交 / 保存中 / 已保存 / 失败”状态。正式页面在长名单下提供不遮挡内容的持续可见汇总和提交入口。提交中禁止重复发起；成功必须以服务器回执为准，响应不确定时查询或用原提交编号重试，不能另起请求造成重复记分。失败和3小时授权过期均保留当前输入，重新授权后复核权限、日期和版本再提交。班级/记录类型切换使用彼此隔离的草稿，切回恢复；离开或刷新导致草稿将丢失时提示，不在浏览器持久存储真实学生名单。

早期样稿仅用于确定交互；正式服务、草稿恢复和移动端验收证据见 implementation-validation.md，不能将样稿结果代替服务端权限与幂等验证。

### 6.1 班级概要事件日志

每班增加“操作记录”页签，仅该班负责人可读，班委账号不获得日志查看权。日志以老师能读懂的一句话概括操作，例如“班委新增「专业课·上午」，记录6人、异常2人”“林老师修改「午间考勤」，2名学生状态变化”“林老师将迟到扣分由1调整为2，应用当前及未来学期”。

记录时间、操作身份类型、可信身份标识（有账号时）、班级、事件类型、活动/规则引用、概要变化、影响人数及来源（网页/后台/未来Agent）。班委日志保存具体账号及当时显示姓名快照；旧共享授权仅标为“班委（旧共享授权）”，不反推个人身份，不记录原始Session ID或Cookie。显示姓名是班主任指定的信息，不宣称实名核验。

覆盖活动新增/修改/删除、新增学生和名单变更、负责人评分规则更新、班委账号创建、名称修改、密码重置和停用等重要业务事件。正常浏览不逐次记入概要日志。只记录“密码已重设”及账号名，不记录密码、token、完整请求、完整学生名单或无关个人资料。

成功业务变更与事件日志同事务提交，失败不得留下成功日志；幂等重试不追加重复成功事件。必要的拒绝/故障记录留在独立诊断或安全审计中，不混入老师的日常操作时间线。老师不能编辑或删除事件日志，活动被删除后其概要日志仍保留名称快照和必要引用。

全局权重更新在同一事务中为负责人名下每个班级各写一条概要事件，包含归档但仍有当前学期数据的班级；不按每名学生重复记日志。事件记录相同的负责人规则修订号，预览范围与日志范围保持一致。班级范围和查看权限由服务器核验。首版不自动清理概要日志；若之后需要保留期限，再单独定义归档政策。日志页显示全学期操作记录，不按顶部学期筛选。

现有 `logger.info` 是运行日志，不满足上述按班级检索、负责人查看和一致性要求。业务审计实体与班级关联应作为结构化数据保存，界面只展示必要摘要。

## 7. Agent 兼容路径

Agent 后续通过受控 API 调用业务服务，不直接读写数据库，也无需模仿网页点击。首轮先确定合同和共用服务边界，不开放实际机器写入口。

建议 `/api/v1/` 合同：班级列表、名单、学期/月汇总、活动列表/详情、创建/修改活动、评分规则预览与更新。返回稳定 ID、分页、时区、学期 ID、规则版本、记录 revision、结构化字段错误；修改传版本，创建/批量写传幂等键。批量写入大小上限和错误是否整体回滚必须明确。

未来机器凭据绑定负责人、允许班级及动作范围，如 `classes:read`、`reports:read`、`activities:write`、`scoring:write`；默认只读，可过期、撤销，服务器只保存凭据散列。类目授权与记录归属都由服务器验证，不能让 Agent 传 owner 参数决定身份。班委的浏览器账号不作为机器凭据。

高影响操作（删除当前学期活动、批量修改当前学期记录、改权重）设计 `preview → commit`：预览返回具体目标、版本和短期操作凭据，提交复核范围、当前学期状态和版本；仅预览不能产生写入。是否要求人工确认由启用该 Agent 的负责人授权策略决定，不给所有请求增加审批负担。已结束学期即使凭据有写权限也禁止修改，不提供历史解锁接口；全量清空、删除班级首版机器接口不开放。

先验证只读调用，再按实际使用需求开放受限写入。明确 Agent 客户端后可加 MCP 薄适配；MCP 调用相同 API/服务、复用权限和审计。远程 MCP 使用其标准授权流程，不把长期 API 密钥直接作为通用 MCP 授权方案。

## 10. R2信息与新增学生输入

## 11. R3月报、凭据复制与导航

月报适配`services/monthly.py`只复用`class_report`的当时名单/规则/归档明细，不另写评分算法。当前显示学期锚定服务器本月和上月；历史学期锚定期末两月。8月、未来月、历史未在册或归档缺失明细均以null及原因表示，不生成0或基础分。`?month=YYYY-MM`严格校验学期归属，学生明细只展示该月记录，明确返回学期明细链接。

班级活动聚合按`occurred_on`位于所选学期半开区间过滤，统计三类记录；最近录入对同一集合取`time`最大值。全员表、单班表及月报输出score_base用于非颜色唯一的分数标记，历史按旧规则基准。

全局导航和班级导航分属独立区域/aria-label，班级标题及面包屑明确当前上下文，手机也不混排。学生次数非零使用朱砂扣分/青绿奖励徽标和数字，0弱化；相对基础分标记只提供阅读辅助，不构成学生合格判定。

凭据加密使用[cryptography Fernet](https://cryptography.io/en/latest/fernet/)；密文载荷绑定account_id/class_id/完整username，取回时同时校验密码散列，拒绝损坏、跨账号移植或旧密文。复制读取只记录“读取登录信息用于复制”，不能把HTTP成功误记为剪贴板成功。新密码和密文同事务保存；复制不引入机器凭据接口。已有账号迁移只添加前缀并撤销会话，不反推旧明文，不改已有日志。

生产异常报告同时过滤JSON请求处理和服务层局部变量，避免只依赖POST字段过滤遗漏密码。开发密钥先写入私有临时文件并fsync，再用独占原子链接发布；多进程首次启动只能采用同一完整密钥，损坏的既有密钥报错而不覆盖。对应异常泄露与双进程竞争均有回归测试。
