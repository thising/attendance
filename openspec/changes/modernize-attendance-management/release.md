## 历史数据为何需要单独确认

旧库没有按学期保存名单与学生身份，只有当前学生以及残存活动、报告、次数缓存。无法从当前 660 人可靠推出某一历史学期的完整名单，也不能把缺少记录证明为没有活动。旧缓存口径和新的自然月口径可能不同。

因此，历史初次导入必须指定可信基线：已有正式报表/学期名单，或经负责人审核的迁移清单。需要为确认的历史学期保存名单、原评分依据、算法标识和不可变报表；确实需要纠错的部分单独列明并取得授权。当前实现预留 `ClassTerm.archived_data` 和 `baseline_source`，**尚未实现经审核清单的正式导入工具**，不得手工清除 `legacy_pending` 来绕过此步骤。

只读工具 `tools/inspect_legacy.py` 检查结构与聚合数据，`tools/compare_legacy_scores.py` 生成有证据范围和假设说明的分数差异。结果见 [历史分数差异](legacy-score-differences.md)。它们不修改数据库，不将候选值认定为已经批准的新历史成绩。

已在副本执行的数据库恢复方式：

```sh
.venv-duxing/bin/python - <<'PY'
import sqlite3
from pathlib import Path
source = Path('.local/backups/pre-modernization-20260922/managedb.sqlite3').resolve()
target = Path('.local/rollback-check.sqlite3').resolve()
if target.exists():
    raise SystemExit('目标已存在，请使用新的演练文件名。')
with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as old:
    with sqlite3.connect(target) as restored:
        old.backup(restored)
        assert restored.execute('PRAGMA integrity_check').fetchone()[0] == 'ok'
target.chmod(0o600)
print('恢复副本完整性检查通过')
PY
```
